One main loop reads a sensor, draws a display and sends a log. Then the display takes 30 ms to draw, and the sensor reading that was due in that time is late. Each new job makes the timing of all the others worse, and the loop fills with counters and flags to work around it. FreeRTOS is a small real-time operating system (RTOS) that removes the problem: you write each job as a separate task, and a scheduler decides which task runs at each moment. In this lesson you rebuild the sensor dashboard as three tasks that pass data through queues and share the buses safely. #STM32 #FreeRTOS #RTOS

## What We Are Building

<Card title="Multitasking Sensor Dashboard" icon="star">
Three independent FreeRTOS tasks: a sensor task that reads the BME280 every 500 ms and pushes data into a queue, a display task that takes it from the queue and updates the SSD1306 OLED, and a logging task that sends readings over UART with DMA. A mutex, a lock only one task can hold at a time, protects the I2C bus shared by the BME280 and the INA219.
</Card>

**Project specifications:**

| Parameter | Value |
|-----------|-------|
| Board | Blue Pill (STM32F103C8T6) |
| RTOS | FreeRTOS v10.5+ (kernel only, no CMSIS-RTOS wrapper) |
| Task: Sensor | Priority 3 (high), 256-word stack, reads BME280 every 500 ms |
| Task: Display | Priority 2 (medium), 256-word stack, updates OLED on queue receive |
| Task: Logger | Priority 1 (low), 256-word stack, formats and sends serial output |
| Task: Idle | Priority 0 (built-in), runs __WFI for low power |
| Queue | 4 slots, each holds a sensor_data_t struct (12 bytes) |
| Mutex | I2C bus access (BME280 and INA219 share I2C1) |
| Parts | Reuse existing (OLED, BME280, serial adapter) |

### FreeRTOSConfig.h

This file sets the size of the system. Three settings matter most at the start: the tick rate, how often the scheduler looks at the tasks (1000 times a second here); the heap, the RAM from which FreeRTOS takes memory for every task and queue (10 KB of the chip's 20 KB); and stack sizes, counted in 4-byte words, not bytes.

```c
#ifndef FREERTOS_CONFIG_H
#define FREERTOS_CONFIG_H

/* Cortex-M3 specific */
#define configCPU_CLOCK_HZ              72000000
/* Do not define configSYSTICK_CLOCK_HZ: the port then clocks SysTick
 * from the core clock. Defining it selects HCLK/8 and the tick runs
 * 8 times too slow. */

/* Scheduler */
#define configUSE_PREEMPTION            1
#define configUSE_TIME_SLICING          1
#define configMAX_PRIORITIES            5
#define configMINIMAL_STACK_SIZE        128   /* Words (512 bytes) */
#define configTICK_RATE_HZ              1000  /* 1 ms tick */
#define configUSE_16_BIT_TICKS          0     /* 32-bit tick counter */

/* Memory */
#define configTOTAL_HEAP_SIZE           10240  /* 10 KB for FreeRTOS heap */
#define configUSE_MALLOC_FAILED_HOOK    1
#define configCHECK_FOR_STACK_OVERFLOW  2

/* Features */
#define configUSE_MUTEXES               1
#define configUSE_COUNTING_SEMAPHORES   1
#define configUSE_QUEUE_SETS            0
#define configUSE_TASK_NOTIFICATIONS    1
#define configUSE_TRACE_FACILITY        1
#define configUSE_IDLE_HOOK             1
#define configUSE_TICK_HOOK             0

/* Cortex-M interrupt priorities */
#define configKERNEL_INTERRUPT_PRIORITY         255
#define configMAX_SYSCALL_INTERRUPT_PRIORITY    80   /* 5 << 4 */
#define configLIBRARY_KERNEL_INTERRUPT_PRIORITY 15
#define configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY 5

/* API functions used in this lesson */
#define INCLUDE_vTaskDelay                  1
#define INCLUDE_uxTaskGetStackHighWaterMark 1

/* Map FreeRTOS handlers to standard names */
#define vPortSVCHandler    SVC_Handler
#define xPortPendSVHandler PendSV_Handler
#define xPortSysTickHandler SysTick_Handler

#endif
```

:::caution[SysTick conflict]
FreeRTOS takes over SysTick for its tick timer. Remove any custom SysTick_Handler from your code. If you need a millisecond counter, use `xTaskGetTickCount()` instead of your own `systick_ms` variable.
:::

## FreeRTOS Core Concepts

<InArticleAd />


### Tasks

A task is a C function with an endless loop, written as if it were the only program on the chip. The processor runs one task at a time, and the scheduler chooses by one rule: of the tasks ready to run, the one with the highest priority runs.

A task that waits (for a delay, for queue data, for a lock) is blocked: not ready, using no processor time. When a higher-priority task becomes ready, the scheduler pauses the running task at once, wherever it is (preemption). The paused task continues later from the same point.

```text
  P3  [Sensor ]             [Sensor ]
  P2           [Display]             [Display]
  P1                    [Logger]
  P0                            [Idle]
      +--------+--------+-------+----+-------> time
      ^        ^        ^            ^
      Sensor   Display  Logger       500 ms later:
      wakes    has data runs last    Sensor wakes again
```

To continue from the same point, a task must find its local variables and return addresses as it left them, so each task has its own stack, private RAM taken from the heap when the task is created: 256 words is 1024 bytes.

```c
/* Task function signature */
void sensor_task(void *params) {
    /* One-time setup */
    bme280_init();

    /* Infinite loop */
    for (;;) {
        /* Do work */
        bme280_read(&data);

        /* Block for 500 ms (yields CPU to other tasks) */
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

/* Create the task */
xTaskCreate(sensor_task,       /* Function */
            "Sensor",          /* Name (for debugging) */
            256,               /* Stack size in words */
            NULL,              /* Parameters */
            3,                 /* Priority (higher = more important) */
            &sensor_handle);   /* Handle (optional) */
```

### Queues

If two tasks share a global variable, one can be paused half-way through writing it, and the other reads a value half old and half new. A queue avoids this: a line of fixed-size slots, like the queue at a counter. One task puts a copy of its data at the back with `xQueueSend()`; another takes the oldest copy from the front with `xQueueReceive()`.

```text
               xDisplayQueue (4 slots)
  +--------+   +--+--+--+--+   +---------+
  | Sensor |-->|  |  |  |  |-->| Display |
  | task   |   +--+--+--+--+   +---------+
  | (P3)   |
  |        |   xLogQueue (4 slots)
  |        |   +--+--+--+--+   +---------+
  |        |-->|  |  |  |  |-->| Logger  |
  +--------+   +--+--+--+--+   +---------+
   xQueueSend                 xQueueReceive
```

A task that receives from an empty queue is blocked, using no processor time, until data arrives. A task that sends to a full queue can wait for a free slot, or give up at once and lose the data. The last argument of each call is the longest time to wait.

```c
/* Data structure passed through the queue */
typedef struct {
    int32_t temperature_c100;    /* Celsius x 100 */
    uint32_t pressure_pa;
    uint32_t humidity_q10;       /* %RH x 10 */
} sensor_data_t;

/* Create a queue with 4 slots */
QueueHandle_t sensor_queue;
sensor_queue = xQueueCreate(4, sizeof(sensor_data_t));
```

### Semaphores

Sometimes a task needs to know only that something happened, with no data. A binary semaphore is a flag for this. One task waits for it ("takes" it) and is blocked. Another task or an interrupt sets it ("gives" it), and the waiting task runs.

```c
/* Binary semaphore: signal that new data is available */
SemaphoreHandle_t data_ready_sem;
data_ready_sem = xSemaphoreCreateBinary();

/* In sensor task: signal new data */
xSemaphoreGive(data_ready_sem);

/* In display task: wait for signal */
xSemaphoreTake(data_ready_sem, portMAX_DELAY);
```

### Mutexes

Two tasks use the I2C bus. If one is paused mid-message and the other starts its own, both messages are spoiled. A mutex (mutual exclusion) is the one key to a room: a task takes it before using the bus and gives it back after. A task that finds it taken is blocked until it is free.

Use a mutex, not a binary semaphore, to protect a bus or a buffer. The reason is priority inheritance, explained under Priority Inversion below.

```c
/* Mutex for I2C bus */
SemaphoreHandle_t i2c_mutex;
i2c_mutex = xSemaphoreCreateMutex();

/* In any task that uses I2C */
if (xSemaphoreTake(i2c_mutex, pdMS_TO_TICKS(100)) == pdTRUE) {
    /* Safe to use I2C */
    bme280_read(&data);
    xSemaphoreGive(i2c_mutex);
} else {
    /* Timeout: could not acquire I2C bus */
}
```

### Sensor Task (Priority 3)

```c
void sensor_task(void *params) {
    (void)params;
    bme280_init();

    sensor_data_t data;

    for (;;) {
        /* Acquire I2C bus */
        if (xSemaphoreTake(i2c_mutex, pdMS_TO_TICKS(100)) == pdTRUE) {
            bme280_read(&data.temperature_c100,
                        &data.pressure_pa,
                        &data.humidity_q10);
            xSemaphoreGive(i2c_mutex);

            /* Send to both queues (the new sample is dropped if a queue is full) */
            xQueueSend(xDisplayQueue, &data, 0);
            xQueueSend(xLogQueue, &data, 0);
        }

        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

### Display Task (Priority 2)

```c
#include <stdio.h>

void display_task(void *params) {
    (void)params;
    oled_init();

    sensor_data_t data;
    char line[32];

    for (;;) {
        /* Wait for data from sensor task */
        if (xQueueReceive(xDisplayQueue, &data, pdMS_TO_TICKS(1000)) == pdTRUE) {
            /* Acquire SPI bus for OLED */
            if (xSemaphoreTake(spi_mutex, pdMS_TO_TICKS(100)) == pdTRUE) {
                oled_clear();

                oled_string(0, 0, "FreeRTOS Dashboard");

                snprintf(line, sizeof(line), "T: %ld.%02ld C",
                         (long)(data.temperature_c100 / 100),
                         (long)(data.temperature_c100 % 100));
                oled_string(0, 16, line);

                snprintf(line, sizeof(line), "P: %lu Pa",
                         (unsigned long)data.pressure_pa);
                oled_string(0, 32, line);

                snprintf(line, sizeof(line), "H: %lu.%lu %%",
                         (unsigned long)(data.humidity_q10 / 10),
                         (unsigned long)(data.humidity_q10 % 10));
                oled_string(0, 48, line);

                oled_update();
                xSemaphoreGive(spi_mutex);
            }
        } else {
            /* Timeout: no data for 1 second */
            if (xSemaphoreTake(spi_mutex, pdMS_TO_TICKS(100)) == pdTRUE) {
                oled_clear();
                oled_string(0, 24, "No sensor data!");
                oled_update();
                xSemaphoreGive(spi_mutex);
            }
        }
    }
}
```

### Logger Task (Priority 1)

```c
void logger_task(void *params) {
    (void)params;

    sensor_data_t data;
    char buf[128];
    uint32_t sample_count = 0;

    for (;;) {
        /* Receive from dedicated log queue */
        if (xQueueReceive(xLogQueue, &data, pdMS_TO_TICKS(2000)) == pdTRUE) {
            sample_count++;
            int len = snprintf(buf, sizeof(buf),
                "[%06lu] T=%ld.%02ldC P=%luPa H=%lu.%lu%%\r\n",
                (unsigned long)sample_count,
                (long)(data.temperature_c100 / 100),
                (long)(data.temperature_c100 % 100),
                (unsigned long)data.pressure_pa,
                (unsigned long)(data.humidity_q10 / 10),
                (unsigned long)(data.humidity_q10 % 10));

            uart_dma_send(buf, len);
        }

        /* The sensor sends 2 samples a second and this task takes 1, so
         * xLogQueue fills and every second sample is dropped by the sender. */
        vTaskDelay(pdMS_TO_TICKS(1000));  /* Log once per second */
    }
}
```

### Idle Hook (Low Power)

When every task is blocked, FreeRTOS runs its own idle task, which calls the first function below. The other two are called by FreeRTOS when the heap is used up or a task writes past the end of its stack.

```c
void vApplicationIdleHook(void) {
    __WFI();  /* Enter sleep until next interrupt */
}

void vApplicationMallocFailedHook(void) {
    /* Heap exhausted: halt for debugger */
    __disable_irq();
    while (1);
}

void vApplicationStackOverflowHook(TaskHandle_t task, char *name) {
    (void)task;
    (void)name;
    /* Stack overflow detected: halt for debugger */
    __disable_irq();
    while (1);
}
```

### Main: Create Tasks and Start Scheduler

```c
int main(void) {
    clock_init();
    uart_init();
    uart_dma_tx_init();
    /* TX-complete interrupt that clears tx_busy for uart_dma_send() */
    NVIC_SetPriority(DMA1_Channel4_IRQn, 6);
    NVIC_EnableIRQ(DMA1_Channel4_IRQn);
    i2c1_init();
    spi1_init();

    rtos_init();  /* Create queues and mutexes */

    xTaskCreate(sensor_task, "Sensor", 256, NULL, 3, NULL);
    xTaskCreate(display_task, "Display", 256, NULL, 2, NULL);
    xTaskCreate(logger_task, "Logger", 256, NULL, 1, NULL);

    uart_send_string("Starting FreeRTOS scheduler...\r\n");

    /* Start the scheduler (never returns) */
    vTaskStartScheduler();

    /* Should never reach here */
    while (1);
}
```

## Priority Inversion: A Practical Example

<InArticleAd />


A lock can make the most important task wait for the least important one. The logger (priority 1) holds the I2C lock when the sensor task (priority 3) wants it, so the sensor task is blocked, correctly. Then the display task (priority 2) becomes ready and preempts the logger, which cannot finish and give the lock back. The sensor task now waits as long as the display task runs: a priority 2 task delays a priority 3 task. This is priority inversion.

```text
  Lock without priority inheritance:

  P3 Sensor:   [run]....blocked on the lock....
  P2 Display:        [runs, preempts Logger ]
  P1 Logger:  [holds lock]....paused..........
```

A FreeRTOS mutex prevents this with priority inheritance: while the sensor task waits, the logger is raised to priority 3, so the display task cannot preempt it. It finishes, gives the mutex back and returns to priority 1.

```text
  Mutex with priority inheritance:

  P3 Sensor:   [run]..blocked..       [run]
  P2 Display:                               [run]
  P1 Logger:  [holds mutex, runs at P3]
```

A binary semaphore has no priority inheritance. So create a lock with `xSemaphoreCreateMutex()`, never with `xSemaphoreCreateBinary()`.

## Debugging FreeRTOS

### Task List in GDB

The stack high water mark is the smallest amount of free stack a task has ever had, in words. If it is near zero, the stack is too small.

```gdb
# FreeRTOS-aware thread list. Start OpenOCD with this extra option first:
#   -c "stm32f1x.cpu configure -rtos FreeRTOS"
info threads

# Examine a specific task's stack
print *((TCB_t *)sensor_handle)

# Check free stack space (stack high water mark)
print uxTaskGetStackHighWaterMark(sensor_handle)
```

### Common FreeRTOS Problems

| Problem | Symptom | Fix |
|---------|---------|-----|
| Stack overflow | Random crashes, corrupted data | Increase stack size, check with watermark |
| Heap exhaustion | Malloc failed hook fires | Increase configTOTAL_HEAP_SIZE |
| Priority inversion | High-priority task starved | Use mutexes (not binary semaphores) |
| Deadlock | Two tasks blocked forever | Always acquire mutexes in the same order |
| Queue overflow | Data lost | Increase queue depth or reduce send rate |
