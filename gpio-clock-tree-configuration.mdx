On an STM32 correct code can switch a pin and nothing happens, with no error: the pin has no clock yet. A wrong clock setting is as quiet: serial text arrives as nonsense and timers run at the wrong speed. In this lesson you map the clock tree, learn every mode of a GPIO pin (general purpose input and output), and wire a KY-040 rotary encoder to the Blue Pill to scroll a menu on a serial terminal. #STM32 #GPIO #ClockTree

## The RCC Clock Tree

<InArticleAd />


A peripheral is a digital circuit, and it moves only when a clock ticks. To save power, every peripheral clock is off after reset; the switches are in the RCC (Reset and Clock Control) module. Enable the clock of a GPIO port, timer or UART there before you use it. If you forget, writes have no effect and reads return zero, with no error: the most common STM32 beginner mistake.

### Clock Sources

Four clock sources. H is high speed (for the system), L low speed (for keeping time); I is internal (on the chip), E external (a crystal on the board).

| Source | Frequency | Notes |
|--------|-----------|-------|
| HSI | 8 MHz | Internal, less accurate, always available |
| HSE | 4 to 16 MHz | External crystal (8 MHz on Blue Pill), accurate |
| LSI | ~40 kHz | Internal, for the watchdog (a timer that resets a frozen program) |
| LSE | 32.768 kHz | External crystal for the real-time clock |

### PLL Configuration

The PLL works like a gearbox for the clock: it takes HSI/2 (4 MHz) or HSE (8 MHz) and multiplies it by 2 to 16. We use $\text{HSE} \times 9 = 72\ \text{MHz}$, the maximum for this chip. The output is the system clock (SYSCLK), which prescalers (dividers) then gear down for three buses. The comparison stops at the mechanism: a PLL is an oscillator held in step with the crystal by feedback, and it needs a moment to lock.

### Bus Architecture

A bus carries a clock and data to a group of peripherals. There are several because not every peripheral can run at 72 MHz.

```
HSE (8 MHz) --> PLL (x9) --> SYSCLK (72 MHz)
                                |
                                +--> AHB (72 MHz, /1)
                                |       |
                                |       +--> APB2 (72 MHz, /1)
                                |       |     GPIO, USART1, SPI1, TIM1, ADC
                                |       |
                                |       +--> APB1 (36 MHz, /2)
                                |             USART2/3, SPI2, TIM2-4, I2C, USB
                                |
                                +--> Cortex System Timer (SysTick)
```

- **AHB** (Advanced High-performance Bus) runs at SYSCLK speed and serves the core and the memory.
- **APB2** (Advanced Peripheral Bus 2) serves the fast peripherals: GPIO, USART1, SPI1, ADC and timer TIM1.
- **APB1** is limited to 36 MHz. It serves USART2/3, SPI2, I2C, timers TIM2 to TIM4 and USB.

A peripheral's bus decides which register holds its clock switch (`APB2ENR` or `APB1ENR`) and which frequency its own dividers start from (72 MHz or 36 MHz). Change one number in the tree and every clock below it changes.

### Enabling Peripheral Clocks

The operator `|=` sets one bit and leaves the other bits of the register as they were.

```c
/* Enable GPIOA clock (APB2 bus) */
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;

/* Enable GPIOB clock (APB2 bus) */
RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;

/* Enable USART1 clock (APB2 bus) */
RCC->APB2ENR |= RCC_APB2ENR_USART1EN;

/* Enable TIM2 clock (APB1 bus) */
RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;
```

:::caution[Clock enable timing]
A newly clocked peripheral needs a few cycles before its registers work. The next instructions usually give enough delay; if not, read the RCC register once first.
:::

## GPIO Modes on STM32F103

<InArticleAd />


One pin can read a switch, drive an LED, or carry a UART or timer signal. You choose with 4 bits per pin, so a 16-pin port needs 64 bits in two 32-bit registers: CRL (configuration register low, pins 0 to 7) and CRH (high, pins 8 to 15). The two MODE bits choose input or output, and how fast an output may switch. The two CNF (configuration) bits set the electrical behavior.

```text
  CRL register: 32 bits, 4 bits for each pin

  Bits: 31..28  27..24  ...  7..4   3..0
  Pin:    7       6     ...   1      0

  The 4 bits of one pin:
  +-----------+------------+
  | CNF [1:0] | MODE [1:0] |
  +-----------+------------+

  Example: PA9 is the second pin of CRH (bits 7..4)
  0xB = 1011: CNF = 10, MODE = 11
```

### The Four GPIO Modes

Four families (input, output, alternate function, analog) give seven settings. Five words first:

- **Push-pull**: the pin drives the line both high and low.
- **Open-drain**: the pin can only pull the line low. A resistor pulls it high, so several chips can share one line.
- **Pull-up or pull-down**: a weak resistor inside the chip holds an unconnected input at a known level, high or low.
- **Floating**: no such resistor. An unconnected floating input reads noise.
- **Alternate function**: a peripheral such as a UART or a timer drives the pin, not your code.

| Mode | MODE bits | CNF bits | Use case |
|------|-----------|----------|----------|
| Input floating | 00 | 01 | Default after reset |
| Input pull-up/pull-down | 00 | 10 | Buttons, encoders |
| Input analog | 00 | 00 | ADC channels |
| Output push-pull | 01/10/11 | 00 | Driving LEDs, signals |
| Output open-drain | 01/10/11 | 01 | I2C, level shifting |
| Alternate function push-pull | 01/10/11 | 10 | UART TX, SPI, PWM |
| Alternate function open-drain | 01/10/11 | 11 | I2C SDA/SCL |

The MODE bits also set the output speed: 00 = input, 01 = 10 MHz, 10 = 2 MHz, 11 = 50 MHz. An output pin should give about 8 mA at most in normal work (25 mA absolute maximum): enough for one LED with its resistor, not for a motor or a relay.

### Configuring a Pin (Register Level)

Set a pin in two steps: clear its 4 bits, then write the new value. Skip the clear and the old bits mix with the new ones (0100 OR 1011 gives 1111, the wrong mode). The position is pin × 4 in CRL, or (pin − 8) × 4 in CRH. The pull direction has no bit of its own: in pull mode the pin's bit in the ODR (output data register) chooses it, 1 for pull-up, 0 for pull-down.

```c
/* PA9 as alternate function push-pull, 50 MHz (USART1 TX) */
/* PA9 is in CRH, position (9-8)*4 = 4 bits starting at bit 4 */
GPIOA->CRH &= ~(0xF << 4);    /* Clear bits [7:4] */
GPIOA->CRH |=  (0xB << 4);    /* MODE=11 (50MHz), CNF=10 (AF push-pull) */

/* PB6 as input with pull-up (encoder CLK) */
/* PB6 is in CRL, position 6*4 = 24 */
GPIOB->CRL &= ~(0xF << 24);   /* Clear bits [27:24] */
GPIOB->CRL |=  (0x8 << 24);   /* MODE=00 (input), CNF=10 (pull-up/down) */
GPIOB->ODR |=  (1 << 6);      /* ODR bit selects pull-UP (vs pull-down) */
```

### Alternate Function Remapping

Some peripheral signals can move from their default pin to a second one through the AFIO (Alternate Function I/O) registers, for example USART1 TX from PA9 to PB6. This lesson uses the default pins.

```c
/* Enable AFIO clock (required for any remapping) */
RCC->APB2ENR |= RCC_APB2ENR_AFIOEN;

/* Example: remap USART1 to PB6/PB7 (not used in this project) */
AFIO->MAPR |= AFIO_MAPR_USART1_REMAP;
```

## Reading the Rotary Encoder

<InArticleAd />


Inside the KY-040 two switches open and close as the knob turns, one a quarter of a step after the other. These quadrature signals, CLK and DT, give one step for each fall of CLK, and their order gives the direction.

Turned clockwise, CLK changes first. At the moment CLK falls, DT is still high:

```text
  Clockwise:
  CLK: ____      ____      ____
           |____|    |____|
  DT:  _______      ____      __
              |____|    |____|
           ^
  CLK falls here, DT = 1
```

Turned counterclockwise, DT changes first. At the moment CLK falls, DT is already low:

```text
  Counterclockwise:
  CLK: _______      ____      __
              |____|    |____|
  DT:  ____      ____      ____
           |____|    |____|
              ^
  CLK falls here, DT = 0
```

So the program reads DT at each fall of CLK: 1 is clockwise, 0 counterclockwise. The push button (SW) is active-low: 0 when pressed.

A mechanical contact bounces: it opens and closes several times in a millisecond or so, and the fast loop sees every bounce. Two rules ignore them (debouncing):

- A fall of CLK counts only after 2 ms of steady high. Its bounces come less than a millisecond apart.
- A press counts only at the change from released to pressed, 50 ms after the last change, so holding the button gives one press.

### Wiring

| KY-040 Pin | Blue Pill Pin | Configuration |
|------------|---------------|---------------|
| CLK | PB6 | Input pull-up |
| DT | PB7 | Input pull-up |
| SW | PB5 | Input pull-up |
| + | 3.3V | Power |
| GND | GND | Ground |

### Encoder Reading Code

```c
typedef struct {
    int16_t position;
    uint8_t last_clk;
    uint32_t clk_change_time;   /* when CLK last changed */
    uint8_t last_sw;
    uint8_t button_pressed;
    uint32_t last_button_time;
} encoder_t;

void encoder_init(encoder_t *enc) {
    /* Enable GPIOB clock */
    RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;

    /* PB5, PB6, PB7 as input with pull-up */
    GPIOB->CRL &= ~(0xFFFU << 20);     /* Clear config for PB5, PB6, PB7 */
    GPIOB->CRL |=  (0x888U << 20);     /* Input with pull-up/pull-down */
    GPIOB->ODR |=  (1 << 5) | (1 << 6) | (1 << 7);  /* Select pull-up */

    enc->position = 0;
    enc->last_clk = (GPIOB->IDR >> 6) & 1;
    enc->clk_change_time = 0;
    enc->last_sw = 1;                  /* released */
    enc->button_pressed = 0;
    enc->last_button_time = 0;
}

void encoder_update(encoder_t *enc, uint32_t tick_ms) {
    uint32_t idr = GPIOB->IDR;         /* read the three pins at one instant */
    uint8_t clk = (idr >> 6) & 1;
    uint8_t dt  = (idr >> 7) & 1;
    uint8_t sw  = (idr >> 5) & 1;

    /* CLK changed: count a fall only after 2 ms of steady high */
    if (clk != enc->last_clk) {
        if (clk == 0 && (tick_ms - enc->clk_change_time) >= 2) {
            if (dt == 1) {
                enc->position++;    /* Clockwise */
            } else {
                enc->position--;    /* Counterclockwise */
            }
        }
        enc->clk_change_time = tick_ms;
        enc->last_clk = clk;
    }

    /* Button: count the change to pressed, 50 ms after the last change */
    if (sw != enc->last_sw && (tick_ms - enc->last_button_time) > 50) {
        if (sw == 0) {
            enc->button_pressed = 1;
        }
        enc->last_sw = sw;
        enc->last_button_time = tick_ms;
    }
}
```

## UART Serial Output

<InArticleAd />


### USART1 Initialization

A UART sends a byte one bit at a time on one wire, and both sides must use the same baud rate (bits per second). The BRR (baud rate register) holds the bus clock divided by the baud rate: USART1 is on APB2, so 72,000,000 / 115,200 = 625. `uart_send_char` waits for an empty transmit register (the TXE bit) before it writes the next byte.

```c
void uart_init(void) {
    /* Enable GPIOA and USART1 clocks */
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN | RCC_APB2ENR_USART1EN;

    /* PA9 (TX) as alternate function push-pull, 50 MHz */
    GPIOA->CRH &= ~(0xF << 4);
    GPIOA->CRH |=  (0xB << 4);

    /* PA10 (RX) as input floating (not used here, but good practice) */
    GPIOA->CRH &= ~(0xF << 8);
    GPIOA->CRH |=  (0x4 << 8);

    /* Baud rate: 115200 at 72 MHz APB2 clock */
    /* BRR = 72000000 / 115200 = 625 = 0x271 */
    USART1->BRR = 0x271;

    /* Enable USART, TX */
    USART1->CR1 = USART_CR1_UE | USART_CR1_TE;
}

void uart_send_char(char c) {
    while (!(USART1->SR & USART_SR_TXE));
    USART1->DR = c;
}

void uart_send_string(const char *str) {
    while (*str) {
        uart_send_char(*str++);
    }
}
```

## Building the Menu System

<InArticleAd />


### SysTick for Timing

The debounce needs the time. SysTick, a small timer inside the core, loaded with 72,000 clock ticks, calls `SysTick_Handler` 1,000 times a second, so `systick_ms` counts milliseconds since start. `volatile` tells the compiler that the variable changes inside an interrupt.

```c
volatile uint32_t systick_ms = 0;

void SysTick_Handler(void) {
    systick_ms++;
}

void systick_init(void) {
    /* SysTick reload: 72 MHz / 1000 = 72000 ticks per ms */
    SysTick->LOAD = 72000 - 1;
    SysTick->VAL = 0;
    SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk |
                    SysTick_CTRL_TICKINT_Msk |
                    SysTick_CTRL_ENABLE_Msk;
}
```

### Menu Display

```c
#define MENU_ITEMS 5

const char *menu_labels[MENU_ITEMS] = {
    "1. LED Brightness",
    "2. Blink Speed",
    "3. Serial Baud Rate",
    "4. Clock Info",
    "5. Reset Settings"
};

void menu_display(int16_t selected) {
    /* ANSI escape: clear screen and move cursor home */
    uart_send_string("\033[2J\033[H");
    uart_send_string("=== STM32 Settings Menu ===\r\n\r\n");

    for (int i = 0; i < MENU_ITEMS; i++) {
        if (i == selected) {
            uart_send_string("  > ");   /* Highlight selected */
        } else {
            uart_send_string("    ");
        }
        uart_send_string(menu_labels[i]);
        uart_send_string("\r\n");
    }

    uart_send_string("\r\nRotate to navigate, press to select.\r\n");
}
```

### Main Loop

```c
int main(void) {
    clock_init();       /* 72 MHz from HSE + PLL */
    systick_init();     /* 1 ms tick */
    uart_init();        /* 115200 baud on PA9 */

    encoder_t enc;
    encoder_init(&enc);

    int16_t last_position = 0;
    int16_t menu_index = 0;

    menu_display(menu_index);

    while (1) {
        encoder_update(&enc, systick_ms);

        /* Update menu on rotation */
        if (enc.position != last_position) {
            int16_t delta = enc.position - last_position;
            last_position = enc.position;

            /* Wrap around, also when several steps arrive at once */
            menu_index = ((menu_index + delta) % MENU_ITEMS + MENU_ITEMS) % MENU_ITEMS;

            menu_display(menu_index);
        }

        /* Handle button press */
        if (enc.button_pressed) {
            enc.button_pressed = 0;
            uart_send_string("\r\nSelected: ");
            uart_send_string(menu_labels[menu_index]);
            uart_send_string("\r\n");

            /* Add action handlers here */
            for (volatile uint32_t i = 0; i < 500000; i++);
            menu_display(menu_index);
        }
    }
}
```

### Testing

The transmit pin (TX) of one device goes to the receive pin (RX) of the other.

```text
  Blue Pill              USB-Serial Adapter
  +----------+           +----------+
  | PA9  TX -+---------->| RX       |
  | PA10 RX -+<----------| TX       |
  | GND -----+-----------| GND      |
  +----------+           +-----+----+
                               |
                            USB to PC
                         (115200 baud)
```

Open a serial terminal at 115200 baud and the menu appears. Turning the encoder scrolls; pressing it prints the selected item.

### Check it

- Turn the knob slowly one full turn. A KY-040 usually has 20 clicks a turn, so the menu goes round its 5 items four times and stops where it started. Anywhere else means lost or doubled steps: check the wiring of CLK and DT.
- Hold the button for two seconds: one "Selected" line, not many.
- Unreadable characters mean a wrong clock, not a wrong program. Without the crystal the chip sends at 8,000,000 / 625 = 12,800 baud.

A redraw takes about 16 ms (188 characters at 115200 baud) and the encoder is not read meanwhile, so a fast spin can lose steps. The timer's encoder mode in the next lesson counts in hardware.
