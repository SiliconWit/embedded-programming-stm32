A sensor or a display is a separate chip that the microcontroller talks to over a few shared wires. Two buses do most of this work, SPI and I2C, and each fails quietly: a blank display, or a program that waits for ever for an answer. You must also choose between ST's ready library (HAL) and your own register code. In this lesson you connect an SSD1306 OLED display over SPI and a BME280 environmental sensor over I2C, write the drivers both ways, and compare their size and speed. #STM32 #SPI #I2C

## SPI on the STM32F103

<InArticleAd />


SPI (Serial Peripheral Interface) is the simple, fast bus. The microcontroller, the master, makes a clock on one wire and sends one bit on another at each tick. Each chip has its own select wire, like a private phone line, and the master pulls it low to say "this is for you". SPI runs at many megahertz, at the cost of one more wire per chip.

- SCK: the clock, made by the master
- MOSI: data from master to chip (master out, slave in)
- MISO: data from chip to master (not used by the display)
- CS: chip select, active low

```text
  Blue Pill              SSD1306 OLED
  +----------+           +----------+
  | PA5 SCK -+---------->| D0 CLK   |
  | PA7 MOSI-+---------->| D1 MOSI  |
  | PA4 CS  -+---------->| CS       |
  | PA3 DC  -+---------->| DC       |
  | PA2 RST -+---------->| RES      |
  | 3.3V ----+---------->| VCC      |
  | GND -----+-----------| GND      |
  +----------+           +----------+

  DC pin: LOW = command, HIGH = data
  CS pin: LOW = selected (active)
```

The STM32F103 has two SPI peripherals: SPI1 on the APB2 bus and SPI2 on APB1. We run SPI1 at 18 MHz ($72\ \text{MHz} / 4$), which is fast enough for an OLED display.

### SPI Configuration Registers

Two control registers, one status register, one data register. To send a byte, the code waits for an empty transmit register (TXE) and writes DR. SPI receives one byte for each byte sent, so the code also waits for RXNE and reads DR. CPOL and CPHA choose the clock edge on which data is read; both chips must use the same setting.

| Register | Key Fields |
|----------|-----------|
| CR1 | MSTR (master mode), BR (baud rate prescaler), CPOL/CPHA (clock polarity/phase), SSM/SSI (software CS), SPE (enable) |
| CR2 | TXEIE/RXNEIE (interrupts), TXDMAEN/RXDMAEN (DMA), SSOE (CS output) |
| SR | TXE (TX empty), RXNE (RX not empty), BSY (busy) |
| DR | Data register (read/write) |

### Register-Level SPI Driver

```c
void spi1_init(void) {
    /* Enable clocks */
    RCC->APB2ENR |= RCC_APB2ENR_SPI1EN | RCC_APB2ENR_IOPAEN;

    /* PA5 (SCK): AF push-pull, 50 MHz */
    /* PA7 (MOSI): AF push-pull, 50 MHz */
    /* PA6 (MISO): Input floating (not used for OLED, but configure anyway) */
    GPIOA->CRL &= ~((0xF << 20) | (0xF << 24) | (0xF << 28));
    GPIOA->CRL |=  ((0xB << 20) | (0x4 << 24) | (0xB << 28));

    /* PA4 (CS), PA3 (DC), PA2 (RST): GPIO output push-pull, 50 MHz */
    GPIOA->CRL &= ~((0xF << 8) | (0xF << 12) | (0xF << 16));
    GPIOA->CRL |=  ((0x3 << 8) | (0x3 << 12) | (0x3 << 16));

    /* CS high (deselected), RST high (not in reset) */
    GPIOA->BSRR = (1 << 4) | (1 << 2);

    /* SPI1 configuration */
    SPI1->CR1 = SPI_CR1_MSTR       /* Master mode */
              | SPI_CR1_SSM        /* Software CS management */
              | SPI_CR1_SSI        /* Internal CS high */
              | (0x1 << 3);       /* Baud rate: fPCLK/4 = 18 MHz */
    /* CPOL=0, CPHA=0 (SSD1306 default), 8-bit data */

    SPI1->CR1 |= SPI_CR1_SPE;     /* Enable SPI */
}

uint8_t spi1_transfer(uint8_t data) {
    while (!(SPI1->SR & SPI_SR_TXE));
    SPI1->DR = data;
    while (!(SPI1->SR & SPI_SR_RXNE));
    return (uint8_t)SPI1->DR;
}

void spi1_send_buf(const uint8_t *buf, uint16_t len) {
    for (uint16_t i = 0; i < len; i++) {
        spi1_transfer(buf[i]);
    }
}
```

### HAL SPI Driver (Comparison)

HAL (hardware abstraction layer) is ST's library. You fill a structure with named settings and call one function, and HAL writes the same registers for you.

```c
/* Using STM32 HAL */
SPI_HandleTypeDef hspi1;

void HAL_SPI1_Init(void) {
    hspi1.Instance = SPI1;
    hspi1.Init.Mode = SPI_MODE_MASTER;
    hspi1.Init.Direction = SPI_DIRECTION_2LINES;
    hspi1.Init.DataSize = SPI_DATASIZE_8BIT;
    hspi1.Init.CLKPolarity = SPI_POLARITY_LOW;
    hspi1.Init.CLKPhase = SPI_PHASE_1EDGE;
    hspi1.Init.NSS = SPI_NSS_SOFT;
    hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_4;
    hspi1.Init.FirstBit = SPI_FIRSTBIT_MSB;
    HAL_SPI_Init(&hspi1);
}

/* Sending data with HAL */
HAL_SPI_Transmit(&hspi1, buf, len, HAL_MAX_DELAY);
```

## SSD1306 OLED Driver

<InArticleAd />


The SSD1306 controls a common one-color 128x64 pixel OLED display. One data wire carries two kinds of byte, so a DC (data/command) pin says which: low for a command, high for pixel data. Initialization is a list of commands from the datasheet.

The program then draws into a framebuffer, a copy of the screen in RAM with one bit per pixel: 128 x 64 / 8 = 1024 bytes. `oled_update()` sends all of it to the display.

### Initialization

```c
#define OLED_CS_LOW()    GPIOA->BRR = (1 << 4)
#define OLED_CS_HIGH()   GPIOA->BSRR = (1 << 4)
#define OLED_DC_CMD()    GPIOA->BRR = (1 << 3)
#define OLED_DC_DATA()   GPIOA->BSRR = (1 << 3)
#define OLED_RST_LOW()   GPIOA->BRR = (1 << 2)
#define OLED_RST_HIGH()  GPIOA->BSRR = (1 << 2)

static uint8_t framebuffer[1024];  /* 128x64 / 8 = 1024 bytes */

void oled_cmd(uint8_t cmd) {
    OLED_DC_CMD();
    OLED_CS_LOW();
    spi1_transfer(cmd);
    OLED_CS_HIGH();
}

void oled_init(void) {
    /* Hardware reset */
    OLED_RST_LOW();
    for (volatile int i = 0; i < 100000; i++);
    OLED_RST_HIGH();
    for (volatile int i = 0; i < 100000; i++);

    oled_cmd(0xAE);  /* Display off */
    oled_cmd(0xD5);  /* Set clock divide */
    oled_cmd(0x80);
    oled_cmd(0xA8);  /* Set multiplex ratio */
    oled_cmd(0x3F);  /* 64 lines */
    oled_cmd(0xD3);  /* Set display offset */
    oled_cmd(0x00);
    oled_cmd(0x40);  /* Set start line to 0 */
    oled_cmd(0x8D);  /* Charge pump */
    oled_cmd(0x14);  /* Enable charge pump */
    oled_cmd(0x20);  /* Memory addressing mode */
    oled_cmd(0x00);  /* Horizontal addressing */
    oled_cmd(0xA1);  /* Segment remap (flip horizontal) */
    oled_cmd(0xC8);  /* COM scan direction (flip vertical) */
    oled_cmd(0xDA);  /* COM pins config */
    oled_cmd(0x12);
    oled_cmd(0x81);  /* Set contrast */
    oled_cmd(0xCF);
    oled_cmd(0xD9);  /* Pre-charge period */
    oled_cmd(0xF1);
    oled_cmd(0xDB);  /* VCOMH deselect level */
    oled_cmd(0x40);
    oled_cmd(0xA4);  /* Display from RAM */
    oled_cmd(0xA6);  /* Normal display (not inverted) */
    oled_cmd(0xAF);  /* Display on */
}

void oled_update(void) {
    oled_cmd(0x21); oled_cmd(0); oled_cmd(127);  /* Column range */
    oled_cmd(0x22); oled_cmd(0); oled_cmd(7);    /* Page range */

    OLED_DC_DATA();
    OLED_CS_LOW();
    spi1_send_buf(framebuffer, 1024);
    OLED_CS_HIGH();
}
```

## I2C on the STM32F103

<InArticleAd />


I2C (Inter-Integrated Circuit) connects many chips with two wires, SCL (clock) and SDA (data), and no select wires. Each chip has an address, and every message begins with the address of the chip wanted, like a call on a shared radio channel that starts with a name. I2C is slower than SPI (400 kHz at most here) but uses fewer pins.

Both lines are open-drain: a chip can only pull a line low, and a resistor (a pull-up) pulls it high again. So several chips can share the lines, and two pulling at once does no harm.

```text
  Blue Pill                   BME280
  +----------+              +----------+
  | PB6 SCL -+------o------>| SCL      |
  | PB7 SDA -+------o<----->| SDA      |
  | GND -----+--------------| GND, SDO |
  | 3.3V ----+------------->| VCC, CSB |
  +----------+              +----------+

  o = a 4.7k resistor from this line to 3.3V
      (already on the BME280 module)
  SDO to GND: address 0x76
  SDO to VCC: address 0x77
```

The STM32F103 I2C peripheral is hard to use at register level: it has known hardware faults (errata), such as a BUSY flag that stays set, and needs register accesses in an exact order. Here HAL saves real debugging time.

### I2C Pin Configuration

I2C pins must be configured as alternate function open-drain. The pull-ups inside the STM32 are too weak for I2C, so the 4.7k resistors on the BME280 module do this work.

### Register-Level I2C Driver

Reading one register of the sensor takes five steps on the bus:

1. START: the master pulls SDA low while SCL is high.
2. The address byte: the 7-bit address shifted left one place, plus 0 for write or 1 for read (0x76 gives 0xEC). The chip with that address answers ACK (acknowledge) by pulling SDA low for one bit.
3. The number of the sensor register wanted.
4. A second START and the address again, now with the read bit (0xED).
5. The sensor sends the data byte. The master answers NACK (no acknowledge: "that was the last byte") and sends STOP.

Each `while` line waits for the flag of one step. If the chip does not answer, the flag never comes and this simple code waits for ever; a driver for real use needs a timeout.

```c
void i2c1_init(void) {
    /* Enable clocks */
    RCC->APB2ENR |= RCC_APB2ENR_IOPBEN | RCC_APB2ENR_AFIOEN;
    RCC->APB1ENR |= RCC_APB1ENR_I2C1EN;

    /* PB6 (SCL), PB7 (SDA): AF open-drain, 50 MHz */
    GPIOB->CRL &= ~((0xF << 24) | (0xF << 28));
    GPIOB->CRL |=  ((0xF << 24) | (0xF << 28));

    /* Reset I2C peripheral */
    I2C1->CR1 |= I2C_CR1_SWRST;
    I2C1->CR1 &= ~I2C_CR1_SWRST;

    /* Configure I2C clock: APB1 = 36 MHz, I2C fast mode 400 kHz */
    I2C1->CR2 = 36;               /* APB1 frequency in MHz */
    I2C1->CCR = I2C_CCR_FS        /* Fast mode */
              | I2C_CCR_DUTY      /* 16:9 duty cycle */
              | 4;                /* 36 MHz / (25 * 4) = 360 kHz (CCR = 3 would give 480 kHz) */
    I2C1->TRISE = 11;             /* Max rise time: (300ns / 27.7ns) + 1 */

    I2C1->CR1 |= I2C_CR1_PE;     /* Enable I2C */
}

uint8_t i2c1_read_reg(uint8_t addr, uint8_t reg) {
    uint8_t data;

    /* Send START */
    I2C1->CR1 |= I2C_CR1_START;
    while (!(I2C1->SR1 & I2C_SR1_SB));

    /* Send slave address (write) */
    I2C1->DR = (addr << 1) | 0;
    while (!(I2C1->SR1 & I2C_SR1_ADDR));
    (void)I2C1->SR2;  /* Clear ADDR flag */

    /* Send register address */
    I2C1->DR = reg;
    while (!(I2C1->SR1 & I2C_SR1_TXE));

    /* Repeated START */
    I2C1->CR1 |= I2C_CR1_START;
    while (!(I2C1->SR1 & I2C_SR1_SB));

    /* Send slave address (read) */
    I2C1->DR = (addr << 1) | 1;
    I2C1->CR1 &= ~I2C_CR1_ACK;   /* NACK after one byte */
    while (!(I2C1->SR1 & I2C_SR1_ADDR));
    (void)I2C1->SR2;

    /* Send STOP */
    I2C1->CR1 |= I2C_CR1_STOP;

    /* Wait for data */
    while (!(I2C1->SR1 & I2C_SR1_RXNE));
    data = (uint8_t)I2C1->DR;

    return data;
}

void i2c1_read_burst(uint8_t addr, uint8_t reg, uint8_t *buf, uint8_t len) {
    I2C1->CR1 |= I2C_CR1_START;
    while (!(I2C1->SR1 & I2C_SR1_SB));

    I2C1->DR = (addr << 1) | 0;
    while (!(I2C1->SR1 & I2C_SR1_ADDR));
    (void)I2C1->SR2;

    I2C1->DR = reg;
    while (!(I2C1->SR1 & I2C_SR1_TXE));

    I2C1->CR1 |= I2C_CR1_START;
    while (!(I2C1->SR1 & I2C_SR1_SB));

    I2C1->DR = (addr << 1) | 1;
    I2C1->CR1 |= I2C_CR1_ACK;
    while (!(I2C1->SR1 & I2C_SR1_ADDR));
    (void)I2C1->SR2;

    for (uint8_t i = 0; i < len; i++) {
        if (i == len - 1) {
            I2C1->CR1 &= ~I2C_CR1_ACK;  /* NACK last byte */
            I2C1->CR1 |= I2C_CR1_STOP;
        }
        while (!(I2C1->SR1 & I2C_SR1_RXNE));
        buf[i] = (uint8_t)I2C1->DR;
    }
}

void i2c1_write_reg(uint8_t addr, uint8_t reg, uint8_t val)
{
    while (I2C1->SR2 & I2C_SR2_BUSY);
    I2C1->CR1 |= I2C_CR1_START;
    while (!(I2C1->SR1 & I2C_SR1_SB));
    I2C1->DR = addr << 1;
    while (!(I2C1->SR1 & I2C_SR1_ADDR));
    (void)I2C1->SR2;
    I2C1->DR = reg;
    while (!(I2C1->SR1 & I2C_SR1_TXE));
    I2C1->DR = val;
    while (!(I2C1->SR1 & I2C_SR1_TXE));
    I2C1->CR1 |= I2C_CR1_STOP;
}
```

### HAL I2C Driver (Comparison)

HAL does all five steps in one call, and the call has a timeout.

```c
I2C_HandleTypeDef hi2c1;

void HAL_I2C1_Init(void) {
    hi2c1.Instance = I2C1;
    hi2c1.Init.ClockSpeed = 400000;
    hi2c1.Init.DutyCycle = I2C_DUTYCYCLE_16_9;
    hi2c1.Init.AddressingMode = I2C_ADDRESSINGMODE_7BIT;

}

/* Reading a register with HAL: one line */
uint8_t data;
```

## BME280 Sensor Driver

<InArticleAd />


### Reading Calibration and Sensor Data

The raw sensor numbers are not degrees. Each BME280 holds its own factory correction numbers (calibration data), which the driver reads once and uses in the datasheet formula. The code below converts only the temperature; pressure and humidity are fixed placeholder values until you add their formulas from the Bosch reference code.

```c
#define BME280_ADDR 0x76

typedef struct {
    uint16_t dig_T1;
    int16_t  dig_T2, dig_T3;
    uint16_t dig_P1;
    int16_t  dig_P2, dig_P3, dig_P4, dig_P5;
    int16_t  dig_P6, dig_P7, dig_P8, dig_P9;
    uint8_t  dig_H1, dig_H3;
    int16_t  dig_H2, dig_H4, dig_H5;
    int8_t   dig_H6;
    int32_t  t_fine;
} bme280_calib_t;

static bme280_calib_t cal;

void bme280_init(void) {
    /* Soft reset */
    i2c1_write_reg(BME280_ADDR, 0xE0, 0xB6);
    for (volatile int i = 0; i < 500000; i++);

    /* Read calibration data */
    uint8_t buf[26];
    i2c1_read_burst(BME280_ADDR, 0x88, buf, 26);

    cal.dig_T1 = (uint16_t)(buf[1] << 8 | buf[0]);
    cal.dig_T2 = (int16_t)(buf[3] << 8 | buf[2]);
    cal.dig_T3 = (int16_t)(buf[5] << 8 | buf[4]);
    cal.dig_P1 = (uint16_t)(buf[7] << 8 | buf[6]);
    cal.dig_P2 = (int16_t)(buf[9] << 8 | buf[8]);
    /* ... remaining calibration values ... */

    /* Configure: humidity x1, temp x1, pressure x1, normal mode */
    i2c1_write_reg(BME280_ADDR, 0xF2, 0x01);  /* ctrl_hum */
    i2c1_write_reg(BME280_ADDR, 0xF4, 0x27);  /* ctrl_meas */
    i2c1_write_reg(BME280_ADDR, 0xF5, 0xA0);  /* config: standby 1s */
}

void bme280_read(int32_t *temp_c100, uint32_t *press_pa, uint32_t *hum_q10) {
    uint8_t raw[8];
    i2c1_read_burst(BME280_ADDR, 0xF7, raw, 8);

    int32_t adc_P = (int32_t)((raw[0] << 12) | (raw[1] << 4) | (raw[2] >> 4));
    int32_t adc_T = (int32_t)((raw[3] << 12) | (raw[4] << 4) | (raw[5] >> 4));
    int32_t adc_H = (int32_t)((raw[6] << 8) | raw[7]);

    /* Temperature compensation (from BME280 datasheet) */
    int32_t var1 = ((((adc_T >> 3) - ((int32_t)cal.dig_T1 << 1)))
                    * ((int32_t)cal.dig_T2)) >> 11;
    int32_t var2 = (((((adc_T >> 4) - ((int32_t)cal.dig_T1))
                    * ((adc_T >> 4) - ((int32_t)cal.dig_T1))) >> 12)
                    * ((int32_t)cal.dig_T3)) >> 14;
    cal.t_fine = var1 + var2;
    *temp_c100 = (cal.t_fine * 5 + 128) >> 8;  /* Celsius x 100 */

    /* Pressure and humidity compensation follow similar formulas */
    /* (full implementation from Bosch reference code) */
    (void)adc_P;
    (void)adc_H;
    *press_pa = 101325;   /* Placeholder */
    *hum_q10 = 500;       /* Placeholder */
}
```

## HAL vs Register Level: The Comparison

<InArticleAd />


The project uses both buses, each with its own chip. SPI1 and I2C1 are separate hardware blocks, so they do not disturb each other.

```text
       STM32F103
  +-----------------+
  | SPI1, 18 MHz    |  SCK, MOSI, CS, DC
  | PA5 PA7 PA4 PA3 +-------------------> SSD1306 OLED
  |                 |
  | I2C1, 360 kHz   |  SCL, SDA
  | PB6 PB7         +<------------------> BME280 sensor
  +-----------------+
```

With both versions built on a Blue Pill, the two compare like this:

| Metric | Register Level | HAL |
|--------|---------------|-----|
| Flash usage (full project) | ~4.2 KB | ~12.8 KB |
| RAM usage | ~1.2 KB | ~1.8 KB |
| SPI byte transfer time | ~0.5 us | ~1.2 us |
| I2C single register read | ~110 us | ~110 us, set by the bus |
| I2C burst read (8 bytes) | ~280 us | ~280 us, set by the bus |
| Lines of driver code | ~180 | ~40 |
| Debug difficulty | Higher (must know registers) | Lower (descriptive API) |

The two I2C rows are calculated, not measured. At 360 kHz one bit takes 2.8 microseconds, and a byte with its acknowledge is 9 bits. A single register read moves 4 bytes, so it takes at least 36 x 2.8 = 100 microseconds. On a slow bus the bus sets the time, not the driver.

### When to Use Which

Use register-level code when:

- flash space is short (bootloaders, very small chips)
- a fast path needs the most speed (switching a pin, a tight timer loop)
- you want to understand the peripheral

Use HAL when:

- development time matters more than program size
- the team needs readable code that moves easily to another STM32 family
- the peripheral is complex (USB, Ethernet) or has known faults, as I2C has here

Many professional projects mix the two.

## Dashboard Main Loop

<InArticleAd />


```c
#include <stdio.h>

int main(void) {
    clock_init();
    systick_init();
    spi1_init();
    i2c1_init();
    oled_init();
    bme280_init();
    uart_init();

    char line[32];
    int32_t temp;
    uint32_t press, hum;

    while (1) {
        bme280_read(&temp, &press, &hum);

        oled_clear();

        /* Title */
        oled_string(0, 0, "STM32 Sensor Hub");

        /* Temperature */
        snprintf(line, sizeof(line), "Temp: %ld.%02ld C",
                 (long)(temp / 100), (long)(temp % 100));
        oled_string(0, 16, line);

        /* Pressure */
        snprintf(line, sizeof(line), "Press: %lu Pa", (unsigned long)press);
        oled_string(0, 32, line);

        /* Humidity */
        snprintf(line, sizeof(line), "Hum: %lu.%lu %%",
                 (unsigned long)(hum / 10), (unsigned long)(hum % 10));
        oled_string(0, 48, line);

        oled_update();

        /* Also print to serial */
        uart_send_string(line);
        uart_send_string("\r\n");

        /* 500 ms delay */
        uint32_t start = systick_ms;
        while ((systick_ms - start) < 500);
    }
}
```
