A hobby servo that receives a slightly wrong signal shakes, turns to the wrong angle, or does not move. It wants one pulse every 20 ms, and the width of that pulse, between 0.5 ms and 2.5 ms, is the angle it turns to. Software delays cannot hold that timing while the program does other work. A timer can. In this lesson you generate the servo signal with one timer, count encoder steps with another, and join both in a pan mechanism that follows the knob. #STM32 #Timers #PWM

## STM32 Timer Overview

<InArticleAd />


A timer is a counter driven by a clock, like a runner who takes one step per tick and runs laps. So one circuit can make a signal with exact timing (PWM), measure an incoming signal (input capture), or count pulses from outside (encoder mode). A channel is one pin connection of a timer, used as an output or an input.

The STM32F103 family timers are below; the STM32F103C8 on the Blue Pill has TIM1 to TIM4.

| Timer | Type | Channels | Resolution | Special Features |
|-------|------|----------|------------|-----------------|
| TIM1 | Advanced | 4 | 16-bit | Extra outputs and safety inputs for motor drives |
| TIM2 | General-purpose | 4 | 16-bit | Encoder mode, PWM, input capture |
| TIM3 | General-purpose | 4 | 16-bit | Encoder mode, PWM, input capture |
| TIM4 | General-purpose | 4 | 16-bit | Encoder mode, PWM, input capture |
| TIM5 | General-purpose | 4 | 16-bit | (High-density F103 parts only, not on the Blue Pill) |
| TIM6 | Basic | 0 | 16-bit | DAC trigger, timebase only (high-density parts only) |
| TIM7 | Basic | 0 | 16-bit | DAC trigger, timebase only (high-density parts only) |

### Timer Clock Source

Every time a timer makes depends on its clock frequency. TIM2, TIM3 and TIM4 are on the 36 MHz APB1 bus, but when the APB1 prescaler divides by more than 1 (here by 2), the chip doubles the timer clock, so they count from 72 MHz. TIM1 is on APB2, also 72 MHz.

### Timer Counting Modes

The counter runs between 0 and the auto-reload register (ARR) value, then starts again, so ARR sets the period. This lesson counts up.

```
Up-counting:    0 -> 1 -> 2 -> ... -> ARR -> 0 -> 1 -> ...
Down-counting:  ARR -> ARR-1 -> ... -> 0 -> ARR -> ARR-1 -> ...
Center-aligned: 0 -> 1 -> ... -> ARR -> ARR-1 -> ... -> 0 -> 1 -> ...
```

## Servo PWM Generation (TIM2)

<InArticleAd />


PWM (pulse width modulation) repeats with a fixed period and is high for part of each period. A hobby servo expects 20 ms (50 Hz), and the pulse width sets the angle: 0.5 ms for 0 degrees, 1.5 ms for 90 degrees (center), 2.5 ms for 180 degrees. The SG90 and many small servos turn about 180 degrees over this range; the standard range every servo accepts is only 1 to 2 ms. A servo that buzzes at an end is pushing against its stop and heats: narrow the range in `servo_set_angle()`.

```text
  |<------------- 20 ms ------------->|
   ___                                 ___
  |   |_______________________________|   |____
  pulse                               next pulse

  Width of the pulse     Angle
  0.5 ms                 0 degrees
  1.5 ms                 90 degrees
  2.5 ms                 180 degrees
```

### PWM Configuration

Three registers of the timer make this signal:

- `PSC` (prescaler) divides the 72 MHz clock by 72, so the counter advances once each microsecond.
- `ARR` is 19,999, so one period is 20,000 counts: 20 ms.
- `CCR1` (compare register) is the pulse width in microseconds. The pin is high while the counter is below `CCR1`, so `CCR1 = 1500` gives a 1.5 ms pulse.

`PSC` and `ARR` hold the wanted number minus 1 (the hardware counts from 0). With preload, a new value waits until the counter starts again, so no pulse is cut in the middle.

```c
void servo_pwm_init(void) {
    /* Enable clocks for GPIOA and TIM2 */
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;
    RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;

    /* PA0 as alternate function push-pull, 50 MHz */
    GPIOA->CRL &= ~(0xF << 0);
    GPIOA->CRL |=  (0xB << 0);

    /*
     * Timer clock = 72 MHz
     * PSC = 72 - 1 = 71   -> counter clock = 1 MHz (1 us per tick)
     * ARR = 20000 - 1      -> period = 20 ms (50 Hz)
     *
     * CCR1 = 500   -> 0.5 ms pulse -> 0 degrees
     * CCR1 = 1500  -> 1.5 ms pulse -> 90 degrees
     * CCR1 = 2500  -> 2.5 ms pulse -> 180 degrees
     */
    TIM2->PSC = 72 - 1;
    TIM2->ARR = 20000 - 1;
    TIM2->CCR1 = 1500;         /* Start at center (90 degrees) */

    /* PWM mode 1 on channel 1, preload enable */
    TIM2->CCMR1 &= ~TIM_CCMR1_OC1M;
    TIM2->CCMR1 |= (0x6 << 4);   /* PWM mode 1 */
    TIM2->CCMR1 |= TIM_CCMR1_OC1PE;  /* Preload enable */

    TIM2->CCER |= TIM_CCER_CC1E;  /* Enable channel 1 output */
    TIM2->CR1 |= TIM_CR1_ARPE;    /* Auto-reload preload */
    TIM2->EGR |= TIM_EGR_UG;      /* Force update to load preload values */
    TIM2->CR1 |= TIM_CR1_CEN;     /* Start timer */
}

void servo_set_angle(uint16_t angle_degrees) {
    if (angle_degrees > 180) angle_degrees = 180;

    /* Map 0-180 degrees to 500-2500 us pulse width */
    uint16_t pulse_us = 500 + (angle_degrees * 2000) / 180;
    TIM2->CCR1 = pulse_us;
}
```

### PWM Output Compare Modes

A match is the moment the counter equals the compare value. PWM is one of eight things the output can do at a match. The OC1M bits choose, and the code above writes 110:

| Mode | OC1M bits | Behavior |
|------|-----------|----------|
| Frozen | 000 | Output unaffected by comparison |
| Active on match | 001 | Set output high on match |
| Inactive on match | 010 | Set output low on match |
| Toggle | 011 | Toggle output on match |
| Force low | 100 | Force output low |
| Force high | 101 | Force output high |
| PWM mode 1 | 110 | High when counter < CCR, low otherwise |
| PWM mode 2 | 111 | Low when counter < CCR, high otherwise |

## Hardware Encoder Interface (TIM3)

<InArticleAd />


The menu program polled the encoder pins in the main loop, so steps were lost whenever the loop was busy. In encoder mode the timer hardware watches both signals and moves its counter up or down by itself.

```text
  +---------+         +-----------------------+
  | Encoder |         | TIM3                  |
  |   CLK --+--PA6--->| TI1   encoder         |
  |   DT  --+--PA7--->| TI2   logic --> CNT   |
  +---------+         +-----------------------+

  CNT rises in one direction and falls in the other.
  The program reads CNT when it wants the position.
```

No step is lost when the CPU is busy, which is why motor control uses this mode.

### Encoder Mode Configuration

Three choices need a reason. Encoder mode 3 counts every edge of both signals, so one KY-040 click gives 4 counts. The input filter needs 8 equal samples at 72 MHz (about 0.1 µs), so it removes electrical spikes, not contact bounce. Bounce does no harm here: only one signal changes at a time, so each bounce counts one step forward and one back. The counter starts at 32,768, the middle of its 16-bit range, so it can move both ways without passing zero.

```c
void encoder_hw_init(void) {
    /* Enable clocks for GPIOA and TIM3 */
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;
    RCC->APB1ENR |= RCC_APB1ENR_TIM3EN;

    /* PA6 (TIM3_CH1) and PA7 (TIM3_CH2) as input floating */
    GPIOA->CRL &= ~((0xF << 24) | (0xF << 28));
    GPIOA->CRL |=  ((0x4 << 24) | (0x4 << 28));

    /*
     * Encoder mode 3: count on both TI1 and TI2 edges
     * This gives 4x resolution (4 counts per detent on KY-040)
     *
     * SMS = 011 (encoder mode 3)
     * CC1S = 01 (IC1 mapped to TI1)
     * CC2S = 01 (IC2 mapped to TI2)
     */
    TIM3->SMCR &= ~TIM_SMCR_SMS;
    TIM3->SMCR |= TIM_SMCR_SMS_0 | TIM_SMCR_SMS_1;  /* Encoder mode 3 */

    TIM3->CCMR1 &= ~(TIM_CCMR1_CC1S | TIM_CCMR1_CC2S);
    TIM3->CCMR1 |= TIM_CCMR1_CC1S_0 | TIM_CCMR1_CC2S_0;

    /* Input filter: IC1F = IC2F = 0011, 8 samples at fCK_INT (rejects spikes under 0.1 us) */
    TIM3->CCMR1 |= (0x3 << 4) | (0x3 << 12);

    /* Set auto-reload to maximum for free-running counter */
    TIM3->ARR = 0xFFFF;

    /* Start at midpoint so we can detect both directions */
    TIM3->CNT = 32768;

    /* Enable the timer */
    TIM3->CR1 |= TIM_CR1_CEN;
}

int16_t encoder_hw_read(void) {
    return (int16_t)(TIM3->CNT - 32768);
}
```

### Encoder Mode Comparison

| Approach | Pros | Cons |
|----------|------|------|
| Software polling (the menu program) | Simple, any GPIO pin | Misses steps under load, uses CPU |
| Hardware encoder mode | Zero CPU usage, never misses steps | Requires specific timer pins |
| External interrupt (EXTI) | Works on any EXTI pin | Interrupt overhead, possible missed edges |

## Input Capture

<InArticleAd />


Input capture is the opposite of PWM: the timer measures a signal from outside. When an edge arrives, the hardware copies the counter into the capture register, like a photo of a clock, so the time is exact even if the program reads it later. Two captures in a row give the period.

```text
  Signal: _____       _________       ____
               |     |         |     |
               |_____|         |_____|
                ^                ^
           capture1          capture2
           (CNT=1000)        (CNT=6000)

  Period = capture2 - capture1
         = 6000 - 1000 = 5000 ticks
  At 1 MHz timer clock: 5000 us = 5 ms
  Frequency = 1 / 0.005 = 200 Hz
```

Input capture measures pulse widths, frequencies and the time between events. The servo project does not use it, but many sensors need it.

### Measuring a Signal Period

The 16-bit counter returns to 0 after 65,535; the 16-bit subtraction in the handler keeps the difference correct when that happens between two captures. At 1 microsecond per count, a period over 65.5 ms cannot be told apart (100 ms reads as 34.5 ms). So the handler notes the SysTick time of each capture and gives 0, meaning "not known", for the first edge, for gaps of 60 ms or more, and once the signal stops. Otherwise a stopped shaft would keep showing its last speed.

```c
extern volatile uint32_t systick_ms;      /* the 1 ms count from the menu program */

volatile uint32_t period_ticks = 0;       /* 0 = not known */
volatile uint32_t last_capture_ms = 0;
static uint16_t last_capture;
static uint8_t have_last = 0;

void input_capture_init(void) {
    /* TIM4 CH1 on PB6 as input capture */
    RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;
    RCC->APB1ENR |= RCC_APB1ENR_TIM4EN;

    /* PB6 as input floating */
    GPIOB->CRL &= ~(0xF << 24);
    GPIOB->CRL |=  (0x4 << 24);

    /* TIM4 prescaler: 72 MHz / 72 = 1 MHz (1 us resolution) */
    TIM4->PSC = 72 - 1;
    TIM4->ARR = 0xFFFF;

    /* CC1 as input, mapped to TI1, rising edge, no filter */
    TIM4->CCMR1 &= ~TIM_CCMR1_CC1S;
    TIM4->CCMR1 |= TIM_CCMR1_CC1S_0;    /* IC1 mapped to TI1 */

    TIM4->CCER &= ~TIM_CCER_CC1P;        /* Rising edge */
    TIM4->CCER |= TIM_CCER_CC1E;         /* Enable capture */

    /* Enable capture interrupt */
    TIM4->DIER |= TIM_DIER_CC1IE;
    NVIC_EnableIRQ(TIM4_IRQn);

    TIM4->CR1 |= TIM_CR1_CEN;
}

void TIM4_IRQHandler(void) {
    if (TIM4->SR & TIM_SR_CC1IF) {
        uint16_t now = TIM4->CCR1;        /* reading CCR1 also clears CC1IF */
        uint32_t gap_ms = systick_ms - last_capture_ms;

        if (have_last && gap_ms < 60) {
            period_ticks = (uint16_t)(now - last_capture);  /* 16-bit counter wraps */
        } else {
            period_ticks = 0;             /* first edge, or too long to measure */
        }
        last_capture = now;
        last_capture_ms = systick_ms;
        have_last = 1;
    }
}

/* Period in microseconds; 0 when no edge came in the last 60 ms */
uint32_t period_us(void) {
    if (systick_ms - last_capture_ms >= 60) return 0;
    return period_ticks;
}
```

## Putting It Together: Servo Pan with Encoder

<InArticleAd />


### Main Application

The loop reads the encoder count and moves the servo 2 degrees for each count. One click of the knob is 4 counts, so it turns the servo 8 degrees.

```c
#include "stm32f103xb.h"
#include <string.h>

/* Forward declarations (implementations from above) */
void clock_init(void);
void systick_init(void);
void uart_init(void);
void uart_send_string(const char *str);
void servo_pwm_init(void);
void servo_set_angle(uint16_t angle);
void encoder_hw_init(void);
int16_t encoder_hw_read(void);
extern volatile uint32_t systick_ms;

/* Simple integer-to-string conversion */
void itoa_simple(int32_t val, char *buf) {
    if (val < 0) { *buf++ = '-'; val = -val; }
    char tmp[12];
    int i = 0;
    do { tmp[i++] = '0' + (val % 10); val /= 10; } while (val);
    while (i > 0) *buf++ = tmp[--i];
    *buf = '\0';
}

int main(void) {
    clock_init();
    systick_init();
    uart_init();
    servo_pwm_init();
    encoder_hw_init();

    /* PB5 as input pull-up for encoder button */
    RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;
    GPIOB->CRL &= ~(0xF << 20);
    GPIOB->CRL |=  (0x8 << 20);
    GPIOB->ODR |=  (1 << 5);

    int16_t last_encoder = 0;
    uint16_t servo_angle = 90;  /* Start centered */
    uint8_t was_pressed = 0;
    uint32_t button_change_ms = 0;
    char buf[32];

    uart_send_string("Servo Pan Controller Ready\r\n");
    uart_send_string("Rotate encoder to pan, press to center.\r\n\r\n");

    while (1) {
        int16_t enc_pos = encoder_hw_read();
        int16_t delta = enc_pos - last_encoder;

        if (delta != 0) {
            last_encoder = enc_pos;

            /* Each encoder count moves servo by 2 degrees (4 counts per detent) */
            int16_t new_angle = (int16_t)servo_angle + (delta * 2);
            if (new_angle < 0) new_angle = 0;
            if (new_angle > 180) new_angle = 180;
            servo_angle = (uint16_t)new_angle;

            servo_set_angle(servo_angle);

            /* Print status */
            uart_send_string("Angle: ");
            itoa_simple(servo_angle, buf);
            uart_send_string(buf);
            uart_send_string(" deg  |  Pulse: ");
            itoa_simple(500 + (servo_angle * 2000) / 180, buf);
            uart_send_string(buf);
            uart_send_string(" us  |  Encoder: ");
            itoa_simple(enc_pos, buf);
            uart_send_string(buf);
            uart_send_string("\r\n");
        }

        /* Button: center once per press (debounced as in the menu program) */
        uint8_t pressed = !(GPIOB->IDR & (1 << 5));
        if (pressed != was_pressed && (systick_ms - button_change_ms) > 50) {
            was_pressed = pressed;
            button_change_ms = systick_ms;
            if (pressed) {
                servo_angle = 90;
                servo_set_angle(90);
                uart_send_string(">> Centered at 90 degrees\r\n");
            }
        }
    }
}
```

### Wiring Summary

| Connection | Wire |
|------------|------|
| PA0 (TIM2_CH1) | Servo signal (orange/yellow wire) |
| PA6 (TIM3_CH1) | Encoder CLK |
| PA7 (TIM3_CH2) | Encoder DT |
| PB5 | Encoder SW (button) |
| PA9 (USART1_TX) | Serial terminal RX |
| 5V | Servo power (red wire) |
| 3.3V | Encoder VCC |
| GND | Common ground (servo, encoder, serial) |

:::caution[Servo power]
PA0 carries only the signal: a pin gives about 8 mA at most, and the SG90 draws up to 500 mA under load, so motor power comes from the red 5V wire. USB power through the Blue Pill may not be enough, especially if the servo stalls. Use a separate 5V supply with its ground joined to the Blue Pill ground.
:::

### Check it

1. Press the button, then turn ten clicks clockwise: the encoder value rises by 40 and the line ends `Angle: 170` and `Pulse: 2388 us`. Four degrees a click means your encoder gives 2 counts a click.
2. Let one timer measure the other: wire PA0 to PB6, call `input_capture_init()` after `systick_init()`, and print `period_us()` each second. Expect 20000, one count either way. (Both timers share one clock, so this checks PSC and ARR, not the crystal.)
3. Pull that wire: `period_us()` gives 0 within 60 ms, not the last 20000.

:::tip[Instrument it]
Input capture and the encoder interface also measure. With a Hall sensor or optical pickup, input capture is a tachometer that reads 0 when the shaft stops; an encoder on a shaft gives position and direction, so firmware can confirm an axis reached its target. The [STM32](/education/sensor-actuator-interfacing-stm32/) closes that loop itself and can [stream](/education/iot-systems/) speed and position to a broker you run, or to [siliconwit.io](https://siliconwit.io), our monitoring service, where drift, slip or a stalled axis shows in the record; it works with any MQTT client.
:::
